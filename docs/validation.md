# Validation workflow and evidence

Run checks appropriate to the changed behaviour. Tests must assess the final output or public contract, rather than copy implementation details. Do not turn an automated image decode into a claim about physical wallet-camera testing.

| Command                          | Evidence                                                                                                                                                                                           |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`                  | Library builds and strict application/test TypeScript checks                                                                                                                                       |
| `npm test`                       | Canonical addresses, invalid inputs, official BIP352 address fixtures, real label-family invariants, independent SHA256 selection, catalogue validity, SVG snapshots and final-image QR decoding   |
| `npm run build`                  | Package verification artifacts and both static pages build                                                                                                                                         |
| `npm run test:packages`          | Local tarballs install into a separate temporary Node/TypeScript project with a fresh npm cache; registry dependencies resolve independently and packaged/standalone SVGs match a committed vector |
| `npm run test:browser`           | Built pages at 320/375/414/768/1280px, browser exports, invalid input, stale-export invalidation, catalogue/family behaviour and local network use                                                 |
| `npm run audit:variety -- 10000` | Sampling coverage and duplicate trait recipes; no proof of global uniqueness                                                                                                                       |
| `npm run audit:visual`           | Exact raster duplicates in 1,024 core characters at 32px and 64px, fixed-label colour/grayscale/colour-vision comparison sheets and exploratory grayscale/colour/outline candidates                |
| `npm run format:check`           | Source formatting without rewriting files                                                                                                                                                          |

Run `npm run build` before package/browser checks. The browser script creates and owns a temporary Vite preview server on port 5287 and closes it afterwards. Chrome defaults to `/usr/bin/google-chrome`; override with `SPIRITS_BROWSER`. If that port belongs to an existing process, resolve ownership or use a separate explicit port rather than killing an unknown process.

Reports and screenshots are in ignored `artifacts/`. Their presence is not proof that they describe the current code: inspect timestamps and session handoffs, or rerun the relevant command. The native Chrome barcode decoder is optional and availability is explicitly reported. jsQR remains independent of the Nayuki encoder even when native decoding is unavailable.

The public page generates automatically. Avatar exports are independent of the background check that gates QR display and exports. Keep operation ownership and immediate output invalidation: changing an address while a decode or PNG conversion is pending must not expose or download the previous input as the new result. Apply ownership to final cleanup and status writes as well as successful results. Invalid fixture controls must invalidate previous lab output before attempting generation.

QR image checks include public fixtures covering every body, head feature, body marking and permanent item in final compositions at integer scales 2 and 3. Separate containment checks cover every body/hem pairing and each remaining feature against the circular frame. This checks the actual larger artwork without clipping it to make a test pass.

The browser suite exercises ordinary responsive widths and enlarged text. Check the bounds of visible child controls in addition to root `scrollWidth`: horizontal clipping can conceal overflowing children. A 200% root-font simulation is useful resize-text evidence, but must be reported separately from native browser zoom and physical-device testing. Test output naming, preview accessibility, known example provenance, invalid fixture generation and overlapping asynchronous operations as public behaviours.

Distribution checks cover the staged package verification artifacts and their integrity. Package consumers use the current manifest and package/build fingerprints so an old tarball cannot satisfy a check after a source or version change. The release workflow retains these files and `SHA256SUMS` in an internal Actions artifact for npm byte verification and manual bootstrap downloads. Public packages download from npm; GitHub release notes link to npm and versioned documentation without custom attachments. GitHub's standard tagged source-code archives are separate from the package staging checks. Browser checks verify that the website links to GitHub and the usage guide and retains required notices. Generated avatar and QR image exports are checked separately.

The package-consumer check installs the local tarballs into an independent project with an initially empty npm cache. It needs registry access for their third-party dependencies. A root `npm ci` can cache dependency tarballs without caching the package metadata needed by a separate install, so this check must not depend on a warm developer cache or force offline resolution.

The visual audit emits `artifacts/visual-vision-sheet.png`, `artifacts/visual-nearest-pairs.png` and a JSON report. Every sample has the same label accents. Grayscale uses linear luminance; protanopia, deuteranopia and tritanopia previews use the full-severity matrices from [Machado, Oliveira and Fernandes (2009)](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/CVD_Simulation.html), applied in linear sRGB. These simulations do not reproduce every person's vision. Colour-vision modes are rendered review sheets; they are not additional exhaustive nearest-pair searches.

Candidate selection compares the union of foreground pixels in a fixed subject crop at 32px. Grayscale compares luminance, colour compares RGB, and outline compares foreground coverage including accessories. Matching unused paper does not improve a score. These are exploratory image distances without human-recognition calibration or a pass threshold.

For a larger candidate pool, run `npm run audit:visual -- 50000 artifacts/my-review`. The first optional argument is a sample count from 2 to 50,000; the second chooses an output directory so historical artifacts can be preserved. Up to 2,048 samples, all pairs receive pixel comparisons. Larger pools use six deterministic projection tables over coarse grayscale, colour-opponent and foreground-coverage blocks, sorted neighbour windows, and bounded candidate lists before fine comparisons. This approximate search can miss close pairs. The report records the method, proposed-pair count, total possible pairs, separate mode rankings and exact raster duplicates. A large sample is not an exhaustive visual-uniqueness proof.

Review selected close pairs at actual 32px and 64px, without relying on label accents, then inspect final composed QRs. Use the [two-memorable-differences art heuristic](artwork.md#composition-checks), and include delayed recognition with similar distractors when organising participant review. Candidate scores, exact pixel differences and an expert visual inspection do not establish a human confusion rate.

Version 0.1 retains experimental artwork and unmeasured recognition goals. Review the final candidate visually and check screen use separately from software decoding; print reliability is unvalidated. A future v1 visual freeze needs its own acceptance review. Local checks do not imply publication, deployment or physical-device results.
